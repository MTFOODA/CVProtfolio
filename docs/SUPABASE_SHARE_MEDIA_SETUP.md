# تفعيل صور روابط المشاركة

تم نشر وظيفة `share-media` يوم 19 نوفمبر 2026 على المشروع الحالي. فحص الاتصال
بعد النشر نجح لكل الخدمات، بما فيها رفض روابط المشاركة غير الصالحة بدل HTTP 404.
الوظيفة تجدّد روابط الصور القديمة والمؤقتة بعد التحقق من صلاحيات المشاركة.
تعديلات عناصر الوصف والتواريخ والإضافات المخصصة تستخدم أعمدة JSON الحالية ولا تحتاج
تغيير الجداول أو إعادة تشغيل ملفات SQL.

افتح PowerShell من مجلد المشروع وشغّل:

```powershell
npx.cmd --yes supabase@3.2.0 login
powershell -NoProfile -ExecutionPolicy Bypass -File tools/deploy_share_media.ps1
python tools/check_supabase.py
```

سجّل الدخول بنفسك في المتصفح الذي يفتحه الأمر الأول. الأمر الثاني يشغّل
اختبارات صلاحيات الصور ثم ينشر الوظيفة للمشروع `shwjiytgrgbpleoljcnk` فقط.
الأمر الأخير يفحص الاتصال من دون جلب بيانات مستخدمين؛ المتوقع نجاح كل
الفحوص بما فيها `share-media deployed`.

الوظيفة تستقبل زائرًا غير مسجل، ثم تتحقق من الرابط وكلمة المرور أو التوكن
بواسطة دوال المشاركة الموجودة. لا توقّع إلا صور الحساب صاحب البورتفوليو
والأقسام والعناصر الظاهرة. إعداد `verify_jwt = false` خاص بهذه الوظيفة؛
لا تغيّر سياسات RLS أو خصوصية الـbucket. مفاتيح الخادم تبقى في Supabase.

بعد النشر جرّب من نافذة خاصة:

1. من الإعدادات الرئيسية افتح إعدادات البورتفوليو وفعّل رابط المشاركة.
2. انسخ رابط `/p/your-slug`، وافتحه كزائر؛ المفروض يظهر البورتفوليو فقط.
3. فعّل الحماية بكلمة مرور واحفظ كلمة المرور؛ جرّب كلمة خاطئة ثم الصحيحة.
4. راجع صورة مشروع وصورة إضافة مخصصة. أخفِ القسم وتأكد من اختفاء محتواه.
5. أوقف رابط المشاركة وتأكد من عدم عرض المحتوى للزائر.

تفاصيل تسجيل Google موجودة في [GOOGLE_OAUTH_SETUP.md](../GOOGLE_OAUTH_SETUP.md).
تفعيل Google على الخادم لا يؤكد نجاح تسجيل حقيقي قبل تجربة حساب Google.

المراجع الرسمية: [نشر الوظائف](https://supabase.com/docs/guides/functions/deploy)،
[مصادقة الوظائف والتحقق داخل المعالج](https://supabase.com/docs/guides/functions/auth).
